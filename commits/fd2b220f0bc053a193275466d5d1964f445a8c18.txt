feat(orchestrator): solo mode — maxParallel 0 does the work itself
With maxParallel set to 0 there are no workers: the orchestrator implements
every ticket itself, in its own session and checkout, one at a time.

- config: normalisation keeps 0 (it used to be coerced to 1), the schema field
  accepts it, /orchestrate parallel 0 switches the session, and the Run screen
  and the wizard's Ready report say "solo"
- context: the worker tools (start, watch, report, prompt, merge) are not
  declared in solo mode, and herdr stops being a capability of the run; the
  per-turn reminder describes doing the work yourself and never mentions a
  worker, a worktree or a slot
- review: the gates judge the checkout — a "changes" gate (working tree against
  the base branch, committed and uncommitted) instead of "commits", clean-tree
  skipped with a reason, forbidden paths and e2e on the same range, and no
  herdr/worktree prerequisite
- close/abort: status-row only, no worktree, branch or worker record
- scan/status/doctor: report the mode and offer exactly one slot (free: 1 while
  nothing is claimed); the model scope is left untouched, because the model the
  orchestrator itself runs on is not a config value
